# yii2-cms-search-tnt — ядро поиска на TNTSearch

Ядро для фасада [`besnovatyj/yii2-cms-search`](../yii2-cms-search/README.md). Полнотекстовый индекс
живёт в той же MySQL, что и контент: на сервере ставить нечего — ни демона, ни порта, ни роли
ansible.

## Что умеет

| Возможность | Есть | Как сделано |
|---|---|---|
| Ранжирование BM25 | да | штатно в TNTSearch |
| Стемминг русского | да | Snowball (`RussianStemmer`), выбирается по `Yii::$app->language` |
| Лемматизация | **нет** | «люди» → «человек» не найдёт; за этим — ядро Manticore |
| Поиск с опечатками | да | многобайтный Левенштейн библиотеки (кириллица считается по символам) |
| Подсветка совпадений | да | текст экранируется до подсветки, наружу идут только `<mark>` |
| Вкладки по разделам | да | собственная карта «документ → раздел» |
| Веса разделов | приблизительно | полевых весов у движка нет: заголовок и ключевые слова повторяются в индексируемой строке, и BM25 поднимает их через частоту |
| Подсказка «возможно, вы имели в виду» | нет | |
| Сортировка по дате | нет | движок хранит только текст |

## Граница применимости

TNTSearch не хранит атрибутов и не фильтрует выдачу. Ядро забирает у него совпадения одним списком
(до **2000** на запрос), после чего фильтрует по разделам и режет на страницы само. Для сайта в
тысячи документов это незаметно; когда типичный запрос начнёт упираться в потолок, пора переходить
на ядро Manticore — контракт фасада, провайдеры модулей и вёрстка выдачи при этом не меняются.

Ориентир заявлен ядром в паспорте возможностей (`comfortableSize`) и виден на странице состояния
индекса в админке.

## Служебные таблицы

Создаются ядром автоматически, миграций modman не требуют (ядро — пакет, а не модуль), полностью
восстановимы переиндексацией — их можно исключать из дампа базы:

* `bescms_search_a_*`, `bescms_search_b_*` — два слота индекса TNTSearch (по пять таблиц);
* `search_tnt_map` — карта «документ → раздел» по слотам;
* `search_tnt_state` — какой слот сейчас рабочий.

Два слота нужны для атомарной подмены: индекс собирается в свободный слот, и рабочим он становится
одним обновлением строки состояния. Поэтому пересборка не оставляет сайт без поиска, а прерванная
сборка не портит рабочий индекс.

## Требования

* MySQL-подключение (`Yii::$app->db`) — реквизиты берутся из него же, отдельных секретов не заводится;
* DSN с `host` (TNTSearch подключается по TCP и не умеет unix-сокет);
* `ext-pdo`, `ext-mbstring`.
